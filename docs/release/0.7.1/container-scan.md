# Container image scan — OAK Community 0.7.1

The `0.7.1` re-scan, run after the pre-launch hardening changed the web image's base to
`nginxinc/nginx-unprivileged` (`RR-037`) — a base change invalidates a scan record, so the
`0.7.0` record ([../0.7.0/container-scan.md](../0.7.0/container-scan.md)) describes images
that no longer ship. This run also produced the image release evidence that closes
`RR-038`: one CycloneDX SBOM per image and an unsigned provenance record, all in this
directory.

Reproduce with:

```bash
make scan-images
```

| | |
|---|---|
| Scanner | `aquasec/trivy:0.74.0`, pinned |
| Platform | `linux/amd64` |
| Method | `docker save` to a tarball, scanned by the scanner container |
| Report | [container-scan.json](container-scan.json) |
| SBOMs | [oak-community-api-image-0.7.1.cdx.json](oak-community-api-image-0.7.1.cdx.json), [oak-community-web-image-0.7.1.cdx.json](oak-community-web-image-0.7.1.cdx.json) |
| Provenance | [image-provenance.json](image-provenance.json) — unsigned, excluded from checksums by design |

The scanner is never given the Docker socket; the SBOMs are generated by the same pinned
scanner from the same exported tarball as the vulnerability scan, so they describe the
image that ships — including its final-stage base — not a build stage.

## Results

| Image | CRITICAL | HIGH | MEDIUM | LOW | UNKNOWN | Fixable CRITICAL/HIGH |
|---|---|---|---|---|---|---|
| API | 3 | 13 | 53 | 58 | 4 | **0** |
| Web | **0** | **0** | **0** | **0** | **0** | **0** |

**Zero fixable findings.** Debian has published no fix for any of the API image's
remaining CRITICAL or HIGH findings — the residue is the set `RR-036` records:
`perl-base` accounts for all three CRITICALs (plus five HIGHs), with single HIGHs in the
`ncurses` family, `gzip` and `libacl1`, and two in `libsqlite3-0`. The UNKNOWN entries are
advisories the scanner's database carries without a severity assignment; none is fixable.

**Rescanned 2026-08-27** against a moved vulnerability database, which is why the counts
differ from the 2026-08-24 scan (HIGH 14 → 13, MEDIUM 49 → 53, UNKNOWN 8 → 4). One
change is substantive rather than bookkeeping: the OpenSSL advisory that was an
unfixable HIGH on 2026-08-24 now **has** a Debian fix (`3.5.7-1~deb13u2`), and the
image's build-time `apt-get upgrade` installs it, so those findings are gone rather than
merely reclassified. The web image picked up the equivalent Alpine fix
(`libcrypto3`/`libssl3` `3.5.8-r0`). This is the scan that matters for a release built
today: the images are rebuilt from their pinned bases on every build, so what ships is
what this scan judged.

The web image — rebased onto `nginxinc/nginx-unprivileged:1.29.1-alpine` and running as
uid 101 — reports **no findings at any severity**.

## The gate

Unchanged from `0.7.0`: `make scan-images` fails on **fixable** CRITICAL or HIGH findings
and reports unfixable ones without failing, `tests/contract/test_image_scan_gate.py` pins
both halves, and the gate stays out of `make check` because it needs Docker and network.
New at `0.7.1`: the release workflow's `images` job runs this same script, so the gate and
the SBOM/provenance evidence now also run in CI, and a fixable finding fails the release
build.
