# ADR-0015: Execute only signed, approved typed runner operations

- Status: Accepted
- Date: 2026-08-14
- Owners: @architecture, @security, @operations
- Requirement IDs: OAK-FR-CTL-005–008, OAK-FR-DEP-001–008, OAK-NFR-SEC-001–004, OAK-NFR-REL-001–002

## Context

Customer-environment runners need powerful target credentials and must translate OAK plans into existing execution systems. Free-form shell generated by an LLM or transported in a bundle would create prompt-injection, confused-deputy, reproducibility and rollback failures. Trusting a request merely because it came from the control plane is insufficient.

## Decision

The compiler emits an immutable `DeploymentBundle` plus a `RunnerPlan` containing only typed operations. Each operation declares a fixed kind, adapter identity/version/digest, adapter parameter-schema digest, typed parameters, artifact and secret references, permission envelope, timeout/retry/idempotency behavior, dependencies, expected state and failure action.

The control plane signs the plan under an explicit verification policy. A target mutation additionally requires a current approval bound to plan/bundle digest, target, action and expiry. The runner independently validates plan, target, lease, policy, approvals, adapter and parameters before target access.

Adapter code maps validated fields to a fixed allowlisted executable and argument vector. It must not use a shell interpreter, plan-selected executable, dynamic downloaded code or free-form command field. The runner resolves secrets locally, journals side effects and returns only evidence allowed by the observation/data contract. Communication is outbound-initiated where possible.

## Alternatives

- **LLM-generated shell reviewed by a human:** rejected; review cannot reliably remove injection, nondeterminism or ambient authority.
- **Signed arbitrary scripts:** rejected; signature establishes origin/integrity, not safety or semantic authorization.
- **Control-plane remote shell/agent:** rejected because it expands inbound attack surface and credential power.
- **Never execute anything:** safe but fails OAK's controlled-installation goal; typed adapters retain bounded execution.

## Consequences

Every deployment backend requires a typed schema, adapter registry entry and contract/adversarial tests. Some tools still run external binaries, but only adapter-constructed argv in an isolated environment. Unsupported operations fail closed. Development shortcuts cannot reach a target. Runner/protocol versioning, signing, key lifecycle and rollback evidence become product responsibilities.

## Revisit triggers

A backend cannot be represented safely, a hardened runner implementation replaces the reference runner, or formal verification/sandbox technology enables a stronger model. No revisit may introduce model-authored arbitrary execution.
