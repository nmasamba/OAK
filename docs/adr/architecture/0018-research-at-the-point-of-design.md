# ADR-0018: Research at the point of design reaches comparison, never approval

- Status: Accepted
- Date: 2026-10-21
- Owners: @architecture, @security, @legal-compliance
- Requirement IDs: OAK-FR-CAT-001–005, OAK-NFR-SEC-003

## Context

OAK Community designs only from a pinned catalogue of three synthetic components. A model created on the Hugging Face Hub yesterday, or a serving runtime released last week whose notes name that model's family, can never appear beside the curated options. Sprint 14 adds research at the point of design: on the user's request, for one case, before its candidates are generated, OAK reads a fixed set of public sources for open models and harnesses that fit the confirmed intent, and shows what passes deterministic gates as alternative designs, each marked new, with its source, its date and how each claim is backed.

That collides with three standing rules. ADR-0011 and `OAK-FR-CAT-001`, `-002` and `-005` make eligibility a human review outcome: a licence `review_status` of `passed`, a `transitive_review` of `passed`, an OSI availability class, a steward's activation. The egress rule in `AGENTS.md` and `docs/build/security-invariants.md` names model providers only. And the governed-pack recipe in `skills.md` forbids "unreviewed live web content" and "popularity as approval". This record says how research meets each: a researched entry reaches comparison, never approval.

The owner's kickoff answers of 2026-10-21 fixed the sources (the Hub, its router and GitHub's REST API, anonymous), the tiers (two), the timing (per run, before candidates exist, behind a consent card) and the designs (unknown estimates, at most two researched designs, a compare-only rule now, and selection as a later sprint).

## Decision

- **Three sources, one egress module, anonymous.**
  - Research reads JSON metadata from exactly three hosts: `huggingface.co` (the Hub's model listing), `router.huggingface.co` (live routes with a price and a probed throughput) and `api.github.com` (repository metadata, releases and a bounded search). No weights, archives or asset downloads, and no `raw.githubusercontent.com`.
  - Every request goes through the one transport module that already serves model providers, with this allowlist, no redirects, no inherited proxy, verified TLS and one deadline per run. The egress rule in `AGENTS.md` and `docs/build/security-invariants.md` now reads "a model provider or a research source". A deterministic generation imports no research module.
  - No credential is stored or sent. GitHub's anonymous budget is 60 core requests an hour per address, shared with every client behind it, and a token would be a second stored credential under ADR-0016; the owner chose anonymous. A run makes at most 30 requests within 60 seconds and is never retried by the worker; a rate limit, a redirect, an oversized body and an unreachable host are each a stable refusal, and an outage is shown as an outage, never as an empty or cached result.
  - The transport carries the status of a refused redirect as a typed field, so research can name a redirect without reading a message. Interpretation's codes and messages do not change.
- **Consent per run, and what leaves the machine.**
  - Research runs only when a case is at `ready_for_candidates` and the user asks for it, and is refused from `candidates_ready` on, so it can never make a recorded report stale. Over REST the capability token is checked first, then the consent, then idempotency and the case version, then the status; a stale or repeated request sends nothing.
  - The consent names every host and the exact terms. The terms are a pure function of the confirmed intent over closed vocabularies kept as data: a capability map (`catalogue/research/capabilities.yaml`), a hardware-class list and a licence list. They carry no brief text, no case id and no credential. The hardware class is derived from the intent's declared hardware numbers and is used on this machine only, to compare an estimated weight floor with the declared memory; no host has a hardware qualifier. The audit event records the digest of the terms.
- **Two tiers.**
  - The Hub's trusted namespaces (the list `huggingface_catalogue.py` already keeps, never widened silently) and an owner-reviewed harness list (`catalogue/research/harness-repositories.yaml`) pass the tier gate on their own evidence.
  - Anything else a bounded search finds is *unvetted*. It is shown with its evidence and enters a design only after the user records a review: a command with a rationale, bound to the snapshot's digest and the item's response digest, appended as an audit event. A review is a recorded human decision, not a toggle, and the gates cannot verify it: a user can accept a repository they should not have.
  - The harness list is drafted and unreviewed at this record. Until the owner sets its review fields, only the trusted namespaces form the trusted tier, so every harness surfaces unvetted. That is the rule working, not failing.
- **Normalisation by allowlist.** Hub, router and GitHub text is author-controlled. Every string is NFKC-normalised and refused if it holds a Unicode category C character. An identifier (namespace, repository, model id, tag) must match an ASCII pattern and is refused when normalisation changes it, which catches full-width lookalikes; trusted namespaces are checked after normalisation. A kept value is a closed enum value or a bounded string from a fixed character class; nothing is stripped by pattern, and what does not fit is dropped. Every displayable string is checked for forbidden words, and a hit refuses the item with a stable reason. A gap is `unknown` with its reason, never a placeholder, a default or a fallback word. No source text reaches an error message, a log, a main slide of the report or a model. Install instructions are data OAK never runs. A renamed or redirected id is refused as a typosquat signal.
- **Honest manifests, and a second rule set.**
  - Each passing item becomes a `component-manifest` stored with `status: quarantined`. A field nobody published takes the schema's honest value: a licence `review_status` of `pending`, a `transitive_review` of `pending`, an `availability_class` of `unknown`, signature, provenance and SBOM statuses of `unknown`, a null support date, empty target and deployment lists, and no minimum resource a source did not publish. A required free-text field says that the source did not publish it. Research never writes `eligible` or `approved_for_context`.
  - A Hub revision and a GitHub tag are git commit ids, never a sha256 of what a runtime loads. They are recorded in the manifest's namespaced `extensions["oak.community/research"]`, with what each digest covers; a sha256 field holds only a published asset digest or the digest of the source's own listing, labelled as such. A model's weight size may be estimated from the stored safetensors element counts and their byte widths; it is labelled an estimate and a floor, never a memory need, and a dtype outside the table or a missing safetensors index makes it `unknown`.
  - Eligibility in the merged snapshot is decided by a second, named rule set, `community-research-gates-1.0.0`, recorded beside the curated `community-open-components-1.0.0`: a licence id on the licence list whose classification is not restricted, source-available, proprietary or unknown; not gated, not archived, not disabled; a release inside the freshness window (180 days by default, recorded on the snapshot); a digest or commit id for what would be installed; a capability in the map; the trusted tier or a recorded accept; no forbidden word. Each failure is a stable `OAK-CAT-*` reason.
  - This scopes ADR-0011 and `OAK-FR-CAT-001`, `-002` and `-005` for researched entries: the curated rules require review outcomes research cannot honestly produce, so a researched entry is eligible for comparison only. The curated reasons that still apply are kept on the entry as visible review items and never dropped; a blocked licence, a known vulnerability or future-dated evidence still makes it ineligible. Nothing becomes `approved_for_context` without a recorded human decision, and this sprint records none.
- **Evidence classes.** Every researched claim carries one class from a closed enum, shown beside it: `served_by_live_route`, `published_release`, `published_by_source`, `measured_by_source`, `claimed_by_model_card`, `claimed_by_release_notes` and `unverified`. Each maps onto `evidenceRef.source_type` with a fixed confidence, and none reads as if OAK checked it: a live route, a dated release and a source's own listing are `vendor_claim` (0.6, 0.7 and 0.6); a probed throughput is `vendor_claim` (0.5), since one probe is not a benchmark; a card's or a release note's words are `community_claim` (0.3); an unverified gap is `inference` (0.0). A research-sourced figure reads "published by source" or "measured by source" in the report, never measured, declared or confirmed. "Works well" and "best" are never asserted; OAK says what each source claims and where. A model's date is the day it was created on the Hub.
- **Pairing by family token.** A harness and a model are paired only when a claim names the pair, and the pairing shows the class of every claim it rests on. The token is the model id's name part with one trailing size segment removed if it matches `-[0-9]+(\.[0-9]+)?[BbMm]$` (`Fixturelm-4B` gives `Fixturelm`; an id without one keeps its whole name). It matches case-insensitively as a whole token inside the release notes: the character before it is not a letter or digit; the character after it is not a letter or digit, and not a `.` or `-` followed by a letter or digit, so `Qwen3` does not match `Qwen3.5` or `Qwen3-Coder`. It is an identifier match, not a reading of free text.
- **Unknown estimates and the compare-only rule.** The router publishes a price and a throughput; nothing publishes quality, operability or energy, and a first-token latency is not a p95. An objective's `value` may therefore be null with an `unknown_reason`, additively for every stored document. In the Pareto comparison an unknown never dominates and is never dominated, and the frontier names the objectives it could not compare. A researched candidate whose hard-constraint results are each a pass, a pending review or an unpublished value is *comparable*: it joins the dominance comparison and a curated candidate's `dominated_by` may name it. Its status stays `infeasible` (feasible still means every hard constraint passes), it keeps every reason, `select` refuses it, and the classification is typed on the candidate, never parsed from a reason.
- **Researched designs.** Candidates are generated from a merged, digested snapshot with its own identity, deterministically given that snapshot and the recorded reviews. One researched design per curated pattern with a model role (at most two), numbered from `candidate-05` in pattern order and never a curated id, holding the newest passing model that fits by Hub creation date and, when a passing harness's claim names it, that harness in a serving role that only a research binding adds (`catalogue/research/bindings/`); the curated patterns and components are not edited. Its label is the pattern label plus the closed suffix "new", never built from a model or repository name; it is never the baseline; and it is listed with its estimates and every reason it cannot be selected. Research adds no lifecycle transition and no MCP tool.
- **The report.** Research enters the architecture report as an appendix present only when the case holds a research snapshot, so an unresearched report is byte-identical. A researched item reaches the main slides only through typed fields: candidate id, closed label, evidence word, date, SPDX id and digest. Quoted claims live in the appendix and never reach the narrator.
- **A fixture source in the shipped image.** A fake research source that reads recorded JSON from a directory is selected only by `OAK_RESEARCH_FIXTURES`, documented as safety-relevant. It is the first test double an environment variable can select in the shipped image, so everything it produces says `source_mode: fixture`, lists no real address and reads "synthetic estimate".

## Alternatives

- **A hosted OAK catalogue service.** Rejected: Community must work without an account or a mandatory hosted dependency (ADR-0012), and a hosted list would be a new trust root.
- **Package registries and leaderboards as sources.** Deferred as their own decision: each is a new host and a new kind of untrusted metadata, and a leaderboard rank is popularity, which never feeds a gate.
- **A stored GitHub token.** Rejected for now: a second credential under ADR-0016 for a budget the sprint does not need.
- **Owner-reviewed lists only.** Rejected: a purely allowlisted search cannot find what is new by definition.
- **Everything that passes the gates is eligible.** Rejected: a typosquatted repository could reach a design with no human in the loop.
- **Research after candidates exist.** Rejected for now: `candidates_ready` moves only to `candidate_selected`, and a lifecycle step would make recorded reports stale.
- **Selectable once reviewed.** The owner's first answer. It needs a recorded declarations review, an evaluation path for non-curated ids and installation image mapping, none of which exist; it is registered as the next sprint rather than done here.

## Consequences

- **New residual risks** `RR-048` to `RR-053`: the terms reveal the shape of what is being designed; quoted claims are labelled, not checked; the anonymous budget is shared; a user review can accept the wrong repository; the fixture source is selectable by configuration; and a commit id is not a digest of what would run.
- **Threat rows change.** `TM-13` gains research as a third trigger and `api.github.com` as a research-only host; `TM-02`, `TM-04`, `TM-14` and `TM-17` gain the research controls and gaps.
- **Two new kinds, two events, two extensions,** all additive, with no migration; the four reference digests, the curated candidates of an unresearched case and the OpenAPI baseline do not move.
- **A larger disclosure.** The README and the status document now describe three things that can leave the machine, each on the user's choice: a brief under a model mode, a report's slide text under a model note mode, and research terms under consent.

## Revisit triggers

- A new source, a token, or research from a later lifecycle status is proposed.
- Selecting a researched design is proposed (the next sprint): it needs the declarations review, the evaluation path and the image mapping named above, and it wakes the report's assurance-status mapping.
- Research or report tools over MCP are proposed.
- The harness list or the licence list is reviewed by the owner, which changes what the trusted tier admits.

Any of these needs a new decision. None may let research approve a component, send brief text, or move the deterministic default.
